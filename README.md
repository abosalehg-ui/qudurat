## 📋 نظرة عامة

**قدراتي** منصة تعليمية تفاعلية مصممة لطلاب المرحلة الثانوية في المملكة العربية السعودية للتدريب على اختبار القدرات العامة (قياس). تجمع المنصة كل ما يحتاجه الطالب في مكان واحد مع تحليل ذكي للأداء. صاحب الفكرة: سلطان بن عامر الرحيلي.

### ✨ لماذا قدراتي؟

- 🎯 **تركيز على الاختبار الحقيقي** — أسئلة تحاكي نمط اختبار قياس، وخيارات تُخلط في كل جلسة كما في الاختبار الفعلي
- 📊 **تحليل ذكي** — تتبع نقاط القوة والضعف تلقائياً، ومقترحات تدريب مبنية على أضعف فئاتك
- 📱 **متجاوب بالكامل** — من 320px إلى الشاشات العريضة
- 🌙 **واجهة عربية** — تصميم RTL كامل مع وضع ليلي وتحكم بحجم الخط
- ♿ **قابل للاستخدام بلوحة المفاتيح** — كل عنصر تفاعلي زر حقيقي، مع تنقّل بالأسهم داخل الخيارات
- 💾 **حفظ تلقائي** — تقدمك محفوظ، وجلستك تُستأنف حتى بعد تحديث الصفحة
- 🔌 **يعمل دون اتصال** — PWA بكل أصولها محلياً بما فيها الخطوط

### 📝 نظام الاختبارات
- ⏱️ **مؤقت زمني** يحاكي ضغط الوقت الحقيقي، مع تحذير عند آخر خمس دقائق ودقيقة
- ✅ **تصحيح تلقائي** ونتائج فورية
- 🔁 **استئناف الجلسة** — تحديث الصفحة أو إغلاق التبويب لا يضيّع اختباراً جارياً

- 🏆 نقاط ومستويات و16 شارة
- 🔖 حفظ الأسئلة للمراجعة لاحقاً

- 💾 نسخ احتياطي واستعادة (JSON) واستيراد/تصدير (CSV)

## 🛠️ التثبيت والاستخدام

### الطريقة 1: الاستخدام المباشر
قم بزيارة [الموقع المباشر](https://abosalehg-ui.github.io/qudurat/) واستخدمه فوراً.

### الطريقة 2: التشغيل المحلي

```bash
git clone https://github.com/abosalehg-ui/qudurat.git
cd qudurat

# التطبيق ملفات ثابتة — أي خادم يكفي
python3 -m http.server 8000     # أو: npm run serve
```

ثم افتح `http://localhost:8000`.

> **مهم:** افتح المشروع عبر خادم لا بـ`file://` — الـ Service Worker وسياسة أمان المحتوى (CSP) تتطلبان مصدراً حقيقياً.

### تشغيل الفحوصات

```bash
npm run check    # سلامة قاعدة الأسئلة (بنية + جودة الشروح)
npm test         # اختبارات الوحدات (node --test، بلا اعتماديات)
npm run verify   # الاثنان معاً — نفس ما يشغّله CI
```

لا يحتاج المشروع إلى `npm install`: **لا توجد أي اعتماديات وقت تشغيل ولا وقت تطوير.**

### الطريقة 3: استضافة على GitHub Pages

1. Fork هذا المستودع
2. Settings ← Pages
3. اختر Branch: `main` و Folder: `/ (root)`

## 📁 هيكل المشروع

```
qudurat/
│
├── 📄 index.html          # هيكل الصفحات — بلا أي معالج أحداث مضمّن (شرط CSP)
├── 📄 styles.css          # كل الأنماط: الرموز التصميمية، الوضع الليلي، الطباعة
├── 📄 fonts.css           # تعريفات @font-face للخطوط المحلية
├── 📁 fonts/              # Tajawal + Amiri (woff2) — لا اعتماد على Google Fonts
├── 📄 app.js              # طبقة الواجهة: التوجيه، الجلسة، العرض، ربط الأحداث
├── 📄 app-core.js         # الدوال النقية المشتركة (قابلة للاختبار في Node)
├── 📄 questions.js        # قاعدة أسئلة واختبارات العينة
├── 📄 service-worker.js   # التخزين المؤقت للعمل دون اتصال (PWA)
├── 📄 manifest.json       # تعريف تطبيق الويب + الأيقونات
├── 📁 scripts/            # check-questions.mjs: فحص سلامة وجودة قاعدة الأسئلة
├── 📁 tests/              # اختبارات وحدات (node --test، بلا اعتماديات)
└── 📁 .github/workflows/  # CI: الفحص + الاختبارات على كل تعديل
```

### أين أضع الكود الجديد؟

| نوع المنطق | الملف | لماذا |
|---|---|---|
| دالة نقية (لا تلمس DOM) | `app-core.js` | تُصدَّر لـNode فتصبح قابلة للاختبار مباشرة |
| عرض أو حالة أو أحداث | `app.js` | تعتمد على DOM |
| قيمة تصنيفية (قسم/فئة/صعوبة) | `app-core.js` فقط | مصدر واحد للحقيقة يستهلكه التطبيق وفاحص CI معاً |

## 💾 تخزين البيانات

| المفتاح | المخزن | المحتوى |
|---------|--------|---------|
| `qudurat_data` | localStorage | محتوى المستخدم (أسئلته المخصصة وتعديلاته) + تقدمه |
| `qudurat_theme` / `qudurat_font_size` | localStorage | تفضيلات العرض |
| `qudurat_admin_pwd` / `qudurat_admin_salt` | localStorage | مشتق PBKDF2 لكلمة مرور اللوحة + ملحها |
| `qudurat_session` | sessionStorage | الجلسة الجارية (للاستئناف بعد التحديث) |
| `qudurat_admin_unlocked` | sessionStorage | حالة فتح اللوحة (تنتهي بإغلاق التبويب) |

**أسئلة العينة لا تُخزَّن إطلاقاً** — تُقرأ من `questions.js` عند كل تشغيل وتُدمج مع محتوى المستخدم، حتى تصل تحديثات المحتوى للمستخدمين الحاليين.

```javascript
// هيكل ما يُحفظ فعلاً
{
  version: 2,
  customQuestions: [...],    // أسئلة أضافها المشرف
  questionOverrides: {...},  // تعديلاته على أسئلة العينة (id -> سؤال)
  deletedQuestionIds: [...],
  customTests: [...],
  deletedTestIds: [...],
  progress: { streak, points, badges, questionsAnswered, categoryProgress, testResults, dailyStats }
}
```

## 🔐 ملاحظة أمنية صريحة

كلمة مرور لوحة التحكم **حماية تنظيمية لا أمنية**. التطبيق كله يعمل في المتصفح بلا خادم، فمن يملك وصولاً للجهاز أو لوحدة تحكم المتصفح يستطيع تجاوزها. الغرض منها منع التعديل العابر على جهاز مشترك.

رغم ذلك تُشتق الكلمة بـPBKDF2 (‏150,000 تكرار، ملح عشوائي) لا بتجزئة بسيطة — لأن كثيراً من المستخدمين يعيدون استخدام كلمات مرورهم، ولا يجوز أن يكشف الجهاز كلمة قد تفتح حساباً آخر.

**لا تضع في هذا التطبيق أي بيانات حساسة.** كل شيء محفوظ نصاً صريحاً في متصفحك.

## 🎨 التخصيص

### تغيير الألوان

في بداية `styles.css` عدّل الرموز في `:root`:

```css
:root {
    --primary: #1a5f7a;
    --secondary: #a35f00;
    --success: #1e8449;
    --danger: #c0392b;
    /* ... */
}
```

> **قبل إدخال أي لون جديد احسب نسبة تباينه** مع الخلفية التي سيظهر فوقها: 4.5:1 للنص العادي و3:1 للنص الكبير (WCAG AA). كل الألوان الحالية مفحوصة.

### إضافة أسئلة جديدة

1. **لوحة التحكم** في الموقع (الأسهل)، أو **استيراد CSV** لدفعة كبيرة
2. **تعديل الكود** مباشرة في `getSampleQuestions()` داخل `questions.js`

```javascript
{
    "id": 501,
    "section": "verbal",          // verbal أو quant
    "subcategory": "analogy",     // من فئات القسم في app-core.js
    "difficulty": "medium",       // easy / medium / hard
    "text": "نص السؤال هنا",
    "options": ["خيار أ", "خيار ب", "خيار ج", "خيار د"],
    "correct": 0,                 // رقم الإجابة الصحيحة (0-3)
    "explanation": "تعليل يوضّح لماذا هذه الإجابة صحيحة تحديداً"
}
```

**الشرح إلزامي وله معيار.** يرفض `npm run check` أي شرح مفقود، أو أقصر من 25 حرفاً، أو من العبارات العامة («الإجابة واضحة»، «حل رياضي مباشر»…). الشرح الذي لا يفيد الطالب الذي أخطأ ليس شرحاً.

الفاحص يرفض أيضاً: المعرفات والنصوص المكررة، والتصنيفات المجهولة، والخيارات المكررة أو الفارغة، وأسئلة الاستيعاب بلا نص سياق.

> **ترتيب الخيارات في البيانات لا يهم** — التطبيق يخلطها في كل جلسة (`shuffleQuestionOptions`)، فلا يستطيع الطالب التخمين بموقع الإجابة.

## 🤝 المساهمة

1. **Fork** المستودع
2. أنشئ فرعاً: `git checkout -b feature/amazing-feature`
3. شغّل `npm run verify` وتأكد أنه أخضر
4. `git commit -m 'وصف واضح للتغيير'` ثم `git push origin feature/amazing-feature`
5. افتح **Pull Request**

### أفكار للمساهمة
- [ ] المزيد من الأسئلة، خصوصاً نصوص استيعاب مقروء أطول وأقرب لطول نصوص قياس الحقيقية
- [ ] مراجعة بشرية لصحة الأسئلة (تحقق آلي جزئي فقط حتى الآن)
- [ ] مزامنة البيانات مع السحابة
- [ ] لوحة صدارة

## 📱 التوافق

المشروع مبني على معايير ويب حديثة مدعومة في كل المتصفحات الرئيسية منذ 2021:
`CSS Grid` · `Custom Properties` · `الخصائص المنطقية (inset-inline)` · `:focus-visible` · `Web Crypto (PBKDF2)` · `Service Worker`.

> **لم يُجرَ اختبار متصفحات شامل.** جرى التحقق آلياً على Chromium فقط (التخطيط عبر ثمانية أحجام شاشة من 320px إلى 1440px، ومسارات التنقّل والتدريب والاختبار ولوحة التحكم). إن واجهتك مشكلة في متصفح معيّن فافتح [issue](https://github.com/abosalehg-ui/qudurat/issues).
